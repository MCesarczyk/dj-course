Strategia Składowania Danych i Pamięci Podręcznej

Sercem systemu jest dwuwarstwowa strategia danych. W tej sekcji przeanalizujesz różnice wydajnościowe pomiędzy różnymi metodami pobierania danych. Zrozumienie tych różnic jest kluczowe dla optymalizacji czasu odpowiedzi systemu (latency).

Porównanie Czasu Dostępu

  • 🗄️

    Zapytanie MongoDB

    Dysk/SSD | Złożoność: O(N) lub O(log N)

    Opóźnienie: 10–50ms

  • ⚡

    Hit w Redis

    RAM | Złożoność: O(1)

    Opóźnienie: 1–3ms

  • 🔄

    Hybryda (Cache Miss)

    RAM + Dysk | Złożoność: O(N) + O(1)

    Opóźnienie: 15–60ms

Matematyka Wydajności

Całkowity czas T dla n żądań, gdzie h to współczynnik trafień (hit rate):

T = n * (h * T_cache + (1 - h) * (T_db + T_cache_write))

Frontend & Infrastruktura

Aplikacja Svelte obsługuje motyw ciemny (Dark Mode) za pomocą zmiennych CSS. Cały stos technologiczny jest orkiestrowany przy użyciu Docker Compose, co gwarantuje spójność środowiska.

🎨 Strategia Motywu Ciemnego

System wykrywa preferencje za pomocą `prefers-color-scheme`. Użycie natywnych zmiennych CSS pozwala Svelte na natychmiastowe renderowanie bez JavaScriptowego "mrugania".

🐳 Infrastruktura jako kod (Docker)

Stosowane są wieloetapowe buildy w celu minimalizacji obrazów (Alpine Linux). Całość działa z uprawnieniami non-root.

Kluczowe Parametry Compose

  • image mongo:latest, redis:alpine
  • build ./backend, ./frontend
  • healthcheck mongosh --eval 'db.runCommand({ping:1})'

Uwaga: Mongo-Express

Zastąpienie zmiennej `ME_CONFIG_MONGODB_SERVER` przez `ME_CONFIG_MONGODB_URL` (pełne URI).

Standardy Profesjonalne Systemu

🔒 Użytkownicy Non-Root 🚀 Bezstanowy Backend (Replikacja) 📉 Minimalizacja CPU przez Redis
